## Projet réel : time-sheet-helper (2026-10-14)

> Les entrées ci-dessus viennent du projet précédent (Librairie Martin / SLIM) importé par erreur ; elles ne s'appliquent PAS ici. Le contexte exact est celui qui suit.

- 2026-10-14 : Projet = **time-sheet-helper** (.NET 10, app Windows locale : tray + Blazor Server + CLI). Collecte des activités (focus, VS Code, Claude Code, Git/GitHub/ADO, Graph) -> `ActivityEvent` -> Engine (règles, groupes, slots 15 min, classification Claude) -> brouillon `TimesheetDraft` -> saisie dans Forecast via MCP. Stockage EF Core SQLite (`%LOCALAPPDATA%\TimeSheetHelper\data.db`, surchargeable par `TIMESHEETHELPER_DATA_DIR`).
- 2026-10-14 : Graphe de projets : `Core` (net10.0, aucune dépendance) <- `Storage` (EF Sqlite 10.0.12) <- `Engine` (Anthropic 12.55.0) / `Forecast` (ModelContextProtocol.Core 1.4.1, DPAPI). `Plugins.Abstractions` (contrat) <- collecteurs `DevOps` (net10.0), `Microsoft365` et `Windows` (net10.0-windows). `App` (Sdk.Web, WinExe, net10.0-windows) n'a PAS de référence d'assembly vers les collecteurs : `BundledPlugin` + cible `StageBundledPlugins` les publient dans `plugins\<dir>\` (windows-activity, devops, microsoft-365) et copient `plugin.json`.
- 2026-10-14 : Modèle de domaine : `ActivityEvent` (classe mutable, UTC, `EndUtc` nul = événement ponctuel, `ExternalId` pour dédoublonnage via index unique filtré `(Source, ExternalId)`). `ActivitySource` = `readonly record struct(string Id)` (pas un enum : extensible par plugins). `SourceTraits`/`SourceBehavior` (Evidence/Presence/NonWork/Meeting) décrivent comment l'engine traite chaque source via `SourceCatalog`. `Rule` (champ/opérateur/motif -> `ForecastTask`, ordre croissant gagne), `ForecastTask` (+ tâche intégrée « ignored »), `TimesheetDraft`/`TimesheetEntry` (heures multiples de 0,25, semaine = lundi), `SlotOverride`, `ClassificationCacheEntry` (empreinte).
- 2026-10-14 : Système de plugins : `plugin.json` (id kebab-case, name, version, apiVersion, entryAssembly .dll à la racine) + une ou plusieurs classes `ISourcePlugin` publiques à constructeur sans paramètre. `Describe()` -> `SourceDescriptor` (Id, Mode Pull/Continuous/Push, Platform, Emits, Config, Secrets, PushRoute, LegacyConfigSection). `Create(IPluginContext)` -> `ISourceInstance` (collectors, Start/Stop, status, actions). `PluginApi.Version = 1` : refus au chargement si différent. `PluginLoadContext` collectible, charge depuis la mémoire (fichiers non verrouillés), partage `System.*`, `Microsoft.Extensions.*`, `Microsoft.AspNetCore.*`, `TimeSheetHelper.Core/Plugins` avec l'hôte. `PluginHost` (IHostedService + `ICollectorSource`) : paquets utilisateur d'abord, remplacent les embarqués ; un plugin défaillant n'empêche pas les autres ; état activé/config persistés en base (`InstalledPlugins`). Mode CLI : `StartForCommandLineAsync` ne démarre que les sources Pull.
- 2026-10-14 : Ingest : `POST /ingest/{route}` (extension VS Code) protégé par jeton aléatoire (`X-TimeSheet-Token`, comparaison `FixedTimeEquals`, jeton dans Credential Manager + fichier `ingest-token`), corps limité à 256 Ko, token vérifié avant lecture du corps, antiforgery désactivé uniquement sur cette route, `/ingest` exclu des pages d'erreur UI.
- 2026-10-14 : Sync : `SyncScheduler` (BackgroundService) — toutes les 30 min (délai initial 2 min), semaine courante + semaine précédente le lundi matin, un `SemaphoreSlim` empêche les chevauchements, un collecteur en échec n'arrête pas les autres. Construit à la main dans `Program.cs` car deux constructeurs (injection ambiguë).
- 2026-10-14 : Auth Microsoft Graph : `GraphAuthenticator` = MSAL public client (`Microsoft.Identity.Client` 4.90.1 + Broker + Extensions.Msal), délégué, scopes `User.Read, Calendars.Read, Mail.ReadBasic, Chat.ReadBasic, ChatMessage.Read`, WAM (SSO Windows) si `UseBroker` sinon navigateur + redirect `http://localhost`, cache DPAPI `msal-microsoft365.cache`, acquisition silencieuse seulement -> `Microsoft365SignInRequiredException` ; `GraphClient` maison (HttpClient, retry/Retry-After sur 429/5xx, paging `@odata.nextLink`). Config TenantId/ClientId non secrets (docs/microsoft365-setup.md).
- 2026-10-14 : Forecast : pas d'API REST, uniquement un serveur MCP avec OAuth dynamique (client enregistré + jetons dans un fichier chiffré DPAPI via `ForecastAuthStore`) ; la soumission pour approbation n'est volontairement PAS implémentée (`NotImplementedException`, à faire à la main).
- 2026-10-14 : Conventions de code observées : constructeurs primaires partout, classes `sealed`, `record` pour résultats/DTO, `Nullable`+`ImplicitUsings`, XML docs `<summary>` en anglais (messages utilisateur en français), `InternalsVisibleTo` vers `TimeSheetHelper.Tests`, une extension `AddXxx` par projet, `IDbContextFactory<TimeSheetDbContext>` (jamais de DbContext injecté), `AsNoTracking` en lecture, enums EF stockés en string. Pas de `Directory.Build.props` ni de gestion centralisée des paquets : versions dans chaque csproj.
- 2026-10-14 : Tests : un seul projet `tests/TimeSheetHelper.Tests` (xUnit 2.9.3, net10.0-windows) + `TimeSheetHelper.TestPlugin` ; sous-dossiers `Engine/`, `Microsoft365/`, `DevOps/`, `App/` ; doubles de test partagés (`Fx`, `FixedTimeProvider` fuseau America/Toronto, `MemorySecretStore`, `FakeClassifier`, `GraphFixtures`, `DevOps/TestDoubles.cs`). Commandes : `dotnet build`, `dotnet test tests/TimeSheetHelper.Tests` (filtre Forecast : `--filter "FullyQualifiedName~Forecast"`).
- 2026-10-14 : Pièges : (1) `PluginLoadContext` ne partage avec l'hôte que des préfixes listés + assemblies déjà dans le contexte par défaut : une nouvelle dépendance partagée mal préfixée provoque des incompatibilités de types entre hôte et plugin ; (2) tout changement de contrat `Plugins.Abstractions` exige `PluginApi.Version` + les `plugin.json` des paquets embarqués ; (3) les tests dépendent du staging des plugins par le build de `.App` (cible `CopyBundledPluginsForTests`) ; (4) les dates doivent passer par `DateTime.SpecifyKind(..., Utc)` avant EF/Graph ; (5) `appsettings.Local.json` (écrit par l'installateur) surcharge la config.
- 2026-10-14 : Dettes/risques repérés : `TrayIcon.cs` ligne ~74 bloque avec `.GetAwaiter().GetResult()` (risque de blocage UI) ; `FileContextResolver` fait `Thread.Sleep(150)` (retry COM) ; versions NuGet incohérentes entre projets (Microsoft.Extensions.Options.ConfigurationExtensions 10.0.0 dans Engine vs 10.0.12 ailleurs, Win32.SystemEvents 10.0.0) faute de gestion centralisée ; `SubmitForApprovalAsync` non implémenté ; `ClaudeClassifier` crée un `AnthropicClient` à chaque appel (pas de réutilisation/HttpClient partagé) ; `GetAccessToken` Graph acquiert le jeton une fois avant la boucle de retry (un jeton expiré pendant un long paging n'est pas renouvelé) ; aucun `.editorconfig` ni analyseurs pour imposer les conventions.
- 2026-10-14 : « Supprimer » un créneau ≠ « Pas du travail ». Pas du travail = `SlotOverride` à `ForecastTaskId` null (`SlotKind.ExcludedByOverride`, activités conservées, visible, réassignable). Supprimer = `WeekService.RemoveSlotsAsync` : table tombstone `RemovedSlots` (migration additive), `SlotKind.Removed` dans l'allocateur, activités effacées seulement si TOUS les créneaux qu'elles touchent (fenêtre résolue, y compris fenêtre d'évidence des événements ponctuels) sont supprimés, sinon conservées et masquées par créneau. Anti-réapparition = masquage côté moteur (pas de garde à l'ingestion, car la fenêtre d'un événement dépend des options du moteur) ; `ActivityStore.WriteAsync` réinsère un segment à `Id` ≠ 0 dont la ligne a été supprimée (sinon `DbUpdateConcurrencyException` dans le collecteur). Piège : `var x = cond ? [] : list.ToList()` ne compile pas (collection expression sans type cible).
- 2026-10-14 : Lookup Forecast (dialogue d'ajout de tâche) : `IForecastLookup`/`ForecastLookup` (Forecast/ForecastLookup.cs, singleton, cache court `ForecastOptions.LookupCacheDuration`). Outils MCP réels vérifiés en direct : `search_projects(name)` (exact P-number/id → objet plat ; texte → `matches` ; aucun → `found:false` + `all_projects` = suggestions à IGNORER) et `find_task(name, project_id?)` (T-number global, texte → `tasks`/`task`). Les numéros de tâche ignorent le scope `project_id` côté serveur : filtrer côté client.
